# Plugin Upgrade Notes: 5.x to 6.0

Delta guidance for updating Elgg plugins from 5.x to 6.0, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/5.x-to-6.0.html>.
The transition raises the PHP requirement to 8.1 (with the `intl` module
now required) and the database minimums to MySQL 8.0 / MariaDB 10.6,
switches JavaScript from RequireJS to native ECMAScript modules, adds a
deletable entity state, removes annotation enable/disable handling, reworks
entity icon metadata, revises headings and the page DOM, and removes a set
of lib and class functions.

## Databases

### DB Requirements

- The minimal MySQL version is now 8.0
- The minimal MariaDB version is now 10.6

### Deleted state

Entities can now be marked as deleted in the database, allowing them to be
restored when a deletion was done too soon.

Because of the changes to `ElggEntity::delete()`, the working of
`ElggFile::delete()` changed: it was previously possible to symlink a file
to a different location (through ways other than Elgg) and delete only the
symlink, not the target file. `ElggFile::delete()` now always deletes both
the symlink and the target file.

## ES Modules

RequireJS is no longer used for the inclusion of AMD JavaScript modules.
Elgg now relies on native ECMAScript modules; all modules can be referenced
under the same name as an importable module.

### Related functions changes

- `elgg_define_js()` — removed; you might need `elgg_register_esm()` as a
  replacement
- `elgg_require_js()` — removed; you might need `elgg_import_esm()` as a
  replacement
- `elgg_unrequire_js()` — removed

The `config`, `amd` event has been removed. The `elgg.data`, `site` event
has been removed — switch to the `elgg.data`, `page` event.

With the switch to ECMAScript modules, Sub-Resource Integrity checks can no
longer be added to imported modules, and JavaScript testing features are
temporarily dropped (they will be added again in the future).

## Composer

### PHP Requirements

The minimal PHP version is now 8.1. The `intl` module is now required to be
enabled.

### PHPUnit

Elgg now uses PHPUnit 10.5; you might need to update your tests.

## Annotations

Due to a naming conflict in the default join alias between the
`annotations` and `metadata` tables, the default join alias for the
`annotations` table has been changed from `n_table` to `a_table`. Code
using very specific clauses (select, where, order_by, etc.) needs updating;
code built with `\Elgg\Database\QueryBuilder` should be fine.

The `enabled` column for annotations has been removed; an annotation is no
longer enabled or disabled. The `enable` and `disable` API calls on
annotations are gone, as are other related API functions.

## Entity Icons

### Cropping coordinates

The cropping coordinates of the default icon (`icon`) are now stored in a
uniform way, same as those of the other icon types. The metadata `x1`,
`x2`, `y1` and `y2` no longer exist; use the new `\ElggEntity` function
`getIconCoordinates()`.

### Icontime

The `icontime` metadata has been removed from the database. It was an
unreliable way to check if an icon was uploaded (and was only stored for
the icon type `icon`). A reliable check is the `\ElggEntity::hasIcon()`
function.

## Headings

Heading usage (h1, h2, h3) has been revisited throughout the codebase so
headings are used when appropriate and in the correct order; see the
accessibility documentation (`/design/a11y`). Most notable:

- H1 is always the page title (no longer the logo / site name)
- Modules (info, sidebar, widgets) use the H2 heading
- H3 headings on entity / relationship / annotation summary titles have
  been replaced by a regular text element

## CSS and HTML structure changes

- Entity summaries and full-view entity pages are wrapped in an `article`
  element
- Sidebar elements now use the `aside` element
- Modules (like widgets or info-modules) now use a `section` element
  instead of a `div`
- Duplicate CSS classes on the same element (like `elgg-body` and
  `elgg-layout-body`) have been removed

The grid helper classes `elgg-grid`, `elgg-col` and `elgg-row` have been
removed; use regular CSS like `display: grid` instead.

Other styling changes include a new background color for the body, improved
breadcrumb styling and a more basic owner block chip.

## Changes in functions

### Removed lib functions

- `elgg_disable_annotations()`
- `elgg_enable_annotations()`
- `elgg_set_view_location()`
- `elgg_strrchr()`
- `elgg_strripos()`
- `elgg_unrequire_css()` — use
  `elgg_unregister_external_file('css', $view)` as replacement

### Removed class functions

- `\ElggAnnotation->enable()`
- `\ElggAnnotation->disable()`
- `\ElggEntity->disableAnnotations()`
- `\ElggEntity->enableAnnotations()`
- `\ElggEntity->getTags()` — use `elgg_get_metadata()` as an alternative

### Lib functions function parameters

- `elgg_get_entity_statistics()` now requires an `array` of `$options` to
  be used by `elgg_get_entities()`
- `elgg_get_simplecache_url()` has the second argument (`$subview`)
  removed; the full `$view` name needs to be provided as the first argument

## Miscellaneous API changes

- The interface `\Elgg\EntityIcon` has been removed; implemented functions
  in `\ElggEntity` have been moved to `\Elgg\Traits\Entity\Icons`
- View names from a `css` or `js` view folder now always need to be
  referenced by their full view name (previously it was possible to omit
  the first folder if it was `css` or `js`)

## Removed Config values

- `system_cache_loaded`
