# Plugin Upgrade Notes: 1.7 to 1.8

Delta guidance for updating Elgg plugins from 1.7 to 1.8, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/1.7-to-1.8.html>.
1.8 standardized plugin structure and reworked the views system; 1.7
deprecations still work but now emit visible errors.

## Updating core

Delete these core directories (same level as `_graphics` and `engine`)
before upgrading — the upgrade breaks if they remain: `_css`, `account`,
`admin`, `dashboard`, `entities`, `friends`, `search`, `settings`,
`simplecache`, `views`.

## Plugin structure

- Page handler URLs: `/page_handler/all`, `/page_handler/owner/:username`,
  `/page_handler/friends/:username`, `/page_handler/view/:guid/:title`,
  `/page_handler/add/:container_guid`, `/page_handler/edit/:guid`,
  `/page_handler/group/:guid/all`. Remove `/pg/` from URLs.
- Page handler scripts live in
  `mod/:plugin/pages/:page_handler/:page_name.php`; handlers must not
  contain HTML. Call `set_input()` for entity GUIDs in the handler and
  `get_input()` in the script; call `gatekeeper()` / `admin_gatekeeper()`
  in the handler when required; push breadcrumbs with
  `elgg_push_breadcrumb()` in the script; no page-owner setup is needed
  for standardized URLs; for group content check the container via
  `elgg_get_page_owner_entity()`. Group URLs use
  `pages/:handler/owner.php`.
- `object/:subtype` views: support both `$vars['full_view']` values
  (replaces `$vars['full']`); find the entity in `$vars['entity']`, verify
  it with `elgg_instance_of()`, and return `true` to short-circuit the view
  when it is missing or of the wrong type; build with
  `elgg_view('object/elements/summary', ...)` and
  `elgg_view_menu('entity', ...)`; keep markup in these views minimal.
- Actions: namespace files and names (`mod/blog/actions/blog/save.php` =>
  `action/blog/save`); use `action/:plugin/save` for add/edit and
  `action/:plugin/delete` for delete; the delete action must accept
  `action/:handler/delete?guid=:guid` so entity menu URLs work by default.
- Forms: move form bodies into `forms/:action` views rendered via
  `elgg_view_form()`; use input views in form bodies rather than raw HTML;
  add a function that prepares the form; make forms sticky.
- Settings views renamed: `plugins/:plugin/settings` (was
  `settings/:plugin/edit`) and `plugins/:plugin/usersettings` (was
  `usersettings/:plugin/edit`).
- `manifest.xml`: add the `<id>` tag (the plugin's directory name under
  `mod/`); never use the `bundled` category — it is reserved for plugins
  distributed with Elgg; bump the plugin version and required
  `elgg_release` when breaking BC.
- CSS/HTML: reuse the core CSS patterns (modules, image block, spacing
  primitives); use hyphens, not underscores, in classes/ids; namespace
  custom CSS with your own prefix, never `elgg-`.
- Widget views and the group profile module must be reworked to the new
  patterns; the blog and file plugins are the reference implementations.
- Functions deprecated in 1.7 produce visible errors in 1.8; many
  registration functions simply gained an `elgg_` prefix. Full list:
  `/engine/lib/deprecated-1.8.php`. Set the debug level to `warning` for
  visual reminders of deprecated usage.
