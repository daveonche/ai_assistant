# Plugin Upgrade Notes: 4.1 to 4.2

Delta guidance for updating Elgg plugins from 4.1 to 4.2, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/4.1-to-4.2.html>.
The transition replaces the Stash cache with Phpfastcache, keeps metadata
and annotation boolean values intact, overhauls the JavaScript libraries,
hardens the `output/url` view, and deprecates the system message
functions among others.

## Stash replaced with Phpfastcache

The internal caching library Stash has been replaced with
[Phpfastcache](https://www.phpfastcache.com/), which is better maintained,
provides more cache drivers and adds more features to the cache
implementation. This change should cause no issues on any existing
installation. If you have Memcache or Redis configured in
`elgg-config/settings.php` you might need to update your configuration.

## Metadata and Annotation boolean values

The database model has been changed to keep boolean values intact between
saving and retrieving. Before this change a saved boolean value was
returned as an integer; now it remains a boolean.

> **Warning**: booleans saved before this change are still integers in
> the database (until saved again).

## System message functions

`system_message()` and `register_error()` have been replaced by
`elgg_register_success_message()` and `elgg_register_error_message()`.
The new functions can pass extra options to the system messages registry.

## Javascript functions

The Elgg JavaScript libraries have gotten a massive overhaul and a lot of
functions have been deprecated. All deprecated functions and globals are
listed in `views/default/core/js/deprecated.js`.

### System messages

If you use system messages in your JavaScript, require the
`elgg/system_messages` module.

### Security tokens

If you use `elgg.security.addToken()` in your JavaScript, require the
`elgg/security` module.

### Translations

If you use `elgg.echo()` in your JavaScript, require the `elgg/i18n`
module.

### UI functions

The user hover menu is no longer initialized from the global `ui.js`;
the JavaScript is required on demand from the `icon/user/default` view.

### ElggUser and ElggEntity

The JavaScript equivalents of `ElggUser` and `ElggEntity` should no longer
be used. The logged in user entity should no longer be referenced in the
`elgg.session.user` page data; its attributes are available in `elgg.user`
as an array.

## Security

The `output/url` view has added security features to help prevent
malicious user generated output. It supports `$vars['allowed_schemes']`,
a list of allowed URL schemes; the provided `$vars['href']` is matched
against that list, and URLs without an allowed scheme are prefixed with
`denied:`. This prevents input like `javascript:alert('just testing');`
from being presented to users.

By default the following schemes are allowed: `http`, `https`, `ftp`,
`sftp`, `ssh`, `file`.

If you use the pattern
`elgg_view('output/url', ['text' => 'something', 'href' => 'javascript:void(0);'])`,
update your code to set `href` to `false`.

## Groups

The menu name for the tabs on the group members page has been replaced to
use the default filter menu logic. Rewrite plugin hooks from
`menu:groups_members` to `menu:filter:groups/members`. Since this is a
different menu, the current group entity is now available in the hook
parameter `filter_entity`.

## Deprecated APIs

### Lib functions

- `elgg_view_menu_item()` — use
  `elgg_view('navigation/menu/elements/item/url', ['item' => $myMenuItem])`
- `register_error()` — use `elgg_register_error_message()`
- `system_message()` — use `elgg_register_success_message()`
