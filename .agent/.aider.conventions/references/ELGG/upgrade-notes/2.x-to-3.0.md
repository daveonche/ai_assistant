# Plugin Upgrade Notes: 2.x to 3.0

Delta guidance for updating Elgg plugins from 2.x to 3.0, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/2.x-to-3.0.html>.
This is the largest transition in the series: it raises the PHP requirement,
removes the multi-site concept and all entity subtables, denormalizes
subtypes and metastrings, replaces raw SQL query options with a
`QueryBuilder` abstraction, introduces named routes and a dependency
injection container, and removes or deprecates hundreds of APIs.

## Detail references

Exhaustive enumerations distilled from this transition live in the
`2.x-to-3.0/` directory next to this file; load them on demand when auditing
a specific removal.

- `2.x-to-3.0/removed-views.md` — all 99 removed views, grouped thematically

## PHP 7.0 is now required

PHP 5.6 is reaching end of life; PHP 7.0 is now required to install and run
Elgg.

## The `$CONFIG` global

The global `$CONFIG` is now a proxy for Elgg's configuration container.
Audit every usage and replace it with `elgg_get_config()` and
`elgg_set_config()`, as recommended since Elgg 1.9. Direct modification of
array properties fails with a NOTICE, e.g. `$CONFIG->cool_fruit[] = 'Pear';`.
`$CONFIG` is no longer available as a local variable inside plugin
`start.php` files.

## Removed views

99 views were removed across layouts, resources, river, search,
notifications, groups and friends, navigation, and bundled assets. The full
enumeration, with replacements, is in `2.x-to-3.0/removed-views.md`.
Highlights: all `page/layouts/*` variants consolidate into
`page/layouts/default`; `page/elements/by_line` is replaced by
`object/elements/imprint`, `output/checkboxes` by `output/tags`, and
`river/item` by `elgg_view_river_item()`; every discussion-reply view is
gone because replies migrated to comments.

## Database schema changes

- Storage engine changes from MyISAM to InnoDB; database settings may need
  optimization for the change.
- The `datalists` table is removed; its settings are merged into the
  `config` table.
- Metastrings are denormalized: the metastrings table is gone and string
  values are stored directly in the metadata and annotation tables. The
  `msv` and `msn` table aliases are no longer available; update custom
  queries and perform your own joins instead of relying on core query
  aliases.
- The `password` and `hash` columns are removed from `users_entity`.
- The unused `geocode_cache` table is removed.
- The `subtype` column in `entities` now holds the subtype string instead of
  an ID, and the `entity_subtypes` table is dropped (see Entity subtypes).
- The `type`, `subtype`, and `access_id` columns are dropped from the
  `river` table. For queries bypassing `elgg_get_river()`, join `entities`
  on `object_guid` to check type and subtype; the access column has been
  unused for some time.
- New installations require MySQL 5.5.3 or higher and use the `utf8mb4`
  character set with LONGTEXT content columns.

## Boolean entity properties

Storage of metadata, annotation, and private setting values is aligned:
booleans are cast to integers on save (`false` as `0`, `true` as `1`). This
breaks private settings, which previously stored `false` as an empty string.
Plugins must migrate stored values from empty strings to `0` so that
`elgg_get_entities()` retrieves them with `private_setting_name_value_pairs`
containing `false`. This applies to plugin settings and entity private
settings alike.

## Metadata changes

- Metadata is no longer access controlled; restrictions on metadata created
  with restricted access will not be honored. Use annotations or entities,
  which do provide access control.
- Do not read or write the `access_id` property on `ElggMetadata` objects.
- Metadata can no longer be enabled or disabled.
- Metadata no longer has an `owner_guid`; querying by `owner_guids` is no
  longer possible, and `ElggMetadata::canEdit()` always returns `true`
  unless a plugin hook overrides it.

## Permissions and access

The user capabilities service no longer triggers permission check hooks when
permissions are checked for an admin user or with access ignored via
`elgg_set_ignore_access()`; plugins can no longer alter permissions in those
cases. `elgg_check_access_overrides()` is removed because overrides no
longer need validation. The translations for the default Elgg access levels
use new language keys.

## Multi site support removed

Partial multi-site support is completely removed. Entities no longer have a
`site_guid` attribute, so entities can no longer live on different sites;
upgrading a database that contains multiple sites fails, and the sites must
be separated into separate databases first. The `member_of_site`
relationship is gone: all related functions are removed and existing
relationships are removed during the upgrade. Setting `ElggSite::$url` has
no effect — the site URL always comes from `$CONFIG->wwwroot` in
`settings.php` or is computed by the Symfony request — and
`ElggSite::save()` fails for any site other than the main site.

## Entity subtables removed

The `sites_entity`, `groups_entity`, `objects_entity`, and `users_entity`
subtables no longer exist; all their attributes moved to metadata. Update
custom queries referencing these tables. `getOriginalAttributes()` now
returns only the base attributes of an entity, no longer the secondary
attributes.

## Friends and group access collections

- The access collections table gains a `subtype` column identifying the
  purpose of the ACL.
- User-owned collections are treated as friends collections and receive the
  `friends_collection` subtype; group ACL information moves from the
  `group_acl` metadata into the ACL subtype attribute.
- `ACCESS_FRIENDS` is migrated to a real access collection with the
  `friends` subtype; entities and annotations are updated to its new id.
  The collection is created with each user, and creating a `friends`
  relationship adds the related guid to it. Entities can no longer be saved
  or updated with the `ACCESS_FRIENDS` access id.

## Entity subtypes

Subtypes are denormalized: the `entity_subtypes` table is removed and the
`entities`.`subtype` column holds the string directly, so all API for
adding, updating, and resolving subtypes and classes is removed. Register
custom entity classes at runtime with `elgg_set_entity_class()` and
`elgg_get_entity_class()` (e.g. in a system init handler). Every entity now
must have a subtype; `user`, `group`, and `site` are added and reserved by
default.

## Custom class loading

Elgg no longer provides class registration APIs. Use PSR-0 classes in the
plugin's `classes` folder or composer autoloading instead.
`elgg_get_class_loader()`, `elgg_register_class()`, and
`elgg_register_classes()` are removed.

## Dependency injection container

Plugins can define their services in an `elgg-services.php` file at the root
of the plugin directory and attach them to Elgg's public DI container. The
`elgg()` function no longer returns the application instance but the DI
container.

## Query building

`elgg_get_entities()` now accepts all options previously spread across
`elgg_get_entities_from_metadata()`, `..._from_annotations()`,
`..._from_relationship()`, `..._from_private_settings()`, and
`..._from_access_id()`, which are deprecated, as are their
`elgg_list_entities_from_*` counterparts.

Passing raw MySQL statements in options is deprecated. Provide closures that
receive an `\Elgg\Database\QueryBuilder` and prepare statements through the
database abstraction layer — this sanitizes values through the database
driver and moves query building to testable, object-oriented code:

```php
elgg_get_entities([
    'wheres' => [
        function (\Elgg\Database\QueryBuilder $qb, $alias) {
            $joined_alias = $qb->joinMetadataTable($alias, 'guid', 'status');
            return $qb->compare(
                "$joined_alias.name",
                'in',
                ['draft', 'unsaved_draft'],
                ELGG_VALUE_STRING
            );
        },
    ],
]);
```

- `wheres` clauses take an `\Elgg\Database\Clauses\WhereClause` instance or
  a closure returning a
  `\Doctrine\DBAL\Query\Expression\CompositeExpression`; `joins`,
  `order_by`, `group_by`, and `selects` take closures returning prepared
  statements.
- The `reverse_order_by` option is removed.
- Do not rely on joined or selected table aliases: closures receive the
  selected table alias as their second argument and must perform their own
  joins.
- The private API around building raw SQL strings is removed. Anything
  marked `@access private` or `@internal` can change or disappear at any
  time; request a public equivalent through a GitHub issue instead of using
  it.

## Routing

`elgg_register_page_handler()` is deprecated in favor of named routes:
register them with `elgg_register_route()` and generate URLs with
`elgg_generate_url()`, or `elgg_generate_entity_url()` as a shortcut for
named routes that depend on entity type and subtype. All core page handlers
are removed and their logic moved to resource views. The `handler` parameter
in entity menus is deprecated in favor of named entity routes. Gatekeeper
functions are refactored into routing middleware: they no longer return
values but throw HTTP exceptions that are routed to error pages and can be
redirected to other pages via hooks.

## Labelling conventions

Entity and collection labelling follows new conventions that the routing and
navigation systems rely on:

- `item:object:blog` — singular entity label
- `collection:object:blog` — plural collection label, with `:all`, `:owner`,
  `:group`, and `:friends` variants
- `add:object:blog` / `edit:object:blog` — action labels

Plugins are advised to follow these conventions.

## Request value filtering

`set_input()` and `get_input()` no longer trim values.

## Action responses

All core and core-plugin actions now use the HTTP response functions
(`elgg_ok_response()`, `elgg_error_response()`) instead of `forward()`, so
in most cases the `forward, system` hook is no longer triggered. Influence
responses through the `response, action:<name>` hook, which targets a
specific action directly.
