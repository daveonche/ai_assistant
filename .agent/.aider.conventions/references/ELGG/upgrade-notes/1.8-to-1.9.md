# Plugin Upgrade Notes: 1.8 to 1.9

Delta guidance for updating Elgg plugins from 1.8 to 1.9, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/1.8-to-1.9.html>.
1.9 rewrote the notifications system, deprecated `$CONFIG` and
`$vars['config']` in favor of `elgg_get_config()`, and moved web services
out of core; the notifications, language-file, river, and entity-URL
changes are not backwards compatible with 1.8.

## Manifest file

No changes are needed for a plugin that is compatible with 1.8. It is
recommended to add the `<id>` tag, whose value is the plugin's directory
name under `mod/`. When a change breaks BC, update the plugin version and
the required `elgg_release`.

## Configuration access

The global `$CONFIG` variable and the `$vars['config']` view parameter are
both deprecated; replace them with `elgg_get_config()` (for example,
`elgg_get_config('plugins_path')`). This change is backwards compatible
with 1.8.

## Language files

- 1.8 language files called `add_translation('en', $english)`; in 1.9 the
  file just returns the translation array, and core derives the language
  from the file name (e.g. `en.php`). Not compatible with 1.8.

## Notifications

The notifications system was rewritten — the biggest 1.9 change. The old
registration style does not carry over (not compatible with 1.8):

- Old: `register_notification_object('object', '<subtype>', ...)` plus a
  `'notify:entity:message', 'object'` hook handler that returned the
  message body.
- New: register the event with
  `elgg_register_notification_event('object', '<subtype>', array('create'))`
  and prepare the message in a
  `'prepare', 'notification:publish:object:<subtype>'` hook handler (the
  official example pairs the `create` event with
  `notification:publish:object:photo`).
- The prepare handler receives an `Elgg_Notifications_Notification` and
  sets its `subject`, `body`, and `summary`; hook params provide `event`
  (with `getObject()` / `getActor()`), `recipient`, `language`, and
  `method`. The `summary` is used, for example, by the
  `site_notifications` plugin.

`notify_user()` still works and stays compatible with 1.8, but it now
accepts a fifth array parameter with `object`, `action`, and `summary`
keys. Include these whenever possible: notification plugins rely on them,
and the bundled `site_notifications` plugin will not work properly without
them.

## Activity listing (river)

- Replace `add_to_river()` with `elgg_create_river_item()`, which takes
  named parameters: `view`, `action_type`, `subject_guid`, and
  `object_guid`.
- The optional `target_guid` parameter names the target of the create
  action (e.g. the album a photo was added to). Not compatible with 1.8.

## Entity URL handlers

`elgg_register_entity_url_handler()` is deprecated. Register a handler for
the `'entity:url', 'object'` plugin hook instead: it receives the entity
in `$params['entity']`, should verify the subtype before acting, and
returns the entity URL. Not compatible with 1.8.

## Web services

The web services API is no longer part of core: enable the "Web services
1.9" plugin and replace every `expose_function()` call with
`elgg_ws_expose_function()`.
