# Plugin Upgrade Notes: 6.x to 7.0

Delta guidance for updating Elgg plugins from 6.x to 7.0, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/6.x-to-7.0.html>.
The major-version transition raises PHP to 8.3 and PHPUnit to 12.5,
replaces Laminas Mail with Symfony Mailer, drops Redis/Memcached caching
and CSS Crush, makes `ElggObject` abstract, and unifies entity forms and
actions on `edit` names.

## Composer

- The minimal PHP version is now 8.3
- Elgg now uses PHPUnit 12.5 — you might need to update your tests
- `laminas/laminas-mail`, `laminas/laminas-mime`, and
  `laminas/laminas-servicemanager` are replaced by `symfony/mailer`;
  the `emailer_transport` config in `elgg-config/settings.php` requires
  a new format (see `elgg-config/settings.example.php`), and
  `emailer_sendmail_settings` / `emailer_smtp_settings` are removed
- The `zend:message, system:email` event is renamed to
  `message, system:email`
- Symfony Mailer uses `proc_open` — PHP hardening may need to allow it
- Font Awesome is updated to version 7; validate icon usage and any
  Font Awesome CSS; custom/pro packs must be updated to version 7

## Elgg core changes

### Default config changes

- The trash is now enabled by default
- `min_password_length` is changed to 16
- Removed config options: `css_compiler_options`, `memcache`,
  `memcache_namespace_prefix`, `memcache_servers`, `redis`,
  `redis_options`, `redis_servers`

### Redis & Memcached

- Built-in support for caching with Redis and Memcached has been removed

### Cron

- The PHP max execution time during CRON is unlimited;
  `set_time_limit(0);` is no longer needed

### CSS Crush removed

- CSS files are no longer preprocessed by CSS Crush; update CSS to use
  `var(--elgg-your-variable)` (variables set in `elgg-plugin.php` or
  core remain available); check custom-theme CSS for CSS Crush features
- The `vars:compiler, css` event has been removed
- The `walled garden` and `maintenance` background-image variables
  changed, and the media-query variables are removed — hardcode them in
  CSS files

### Color Scheme changes

- New CSS variables and changed CSS configuration support color schemes;
  custom themes may need updates
- The `elgg-button-special` and `elgg-button-action-done` button classes
  are removed

### Entity restore

- The `entity/chooserestoredestination` form and action now use a
  singular `destination_container_guid` value

### Entity listings

- `elgg_list_entities()` limits the `limit` parameter (e.g.,
  `/blog/all?limit=20`) to a minimum of 1 and a maximum of 100

### River emittable capability

- River activity is controlled by the `river_emittable` capability; add
  it to the `capabilities` configuration in `elgg-plugin.php`

### Abstract ElggObject

- `ElggObject` is now abstract; each custom object subtype requires its
  own extension of the class

### Response event

- The `response` and `ajax_response` event types changed: the former
  `path` is replaced by `route_name` (path agnostic), and
  `ajax_response` is replaced by `ajax_results`, which influences only
  the data — update event handlers as needed

### Ajax route

- The `ajax` route definition splits `segments` into `type` and
  `segments`; URL generation may need updates

### Notifications

- Handlers moved and renamed:
  - `Elgg\Notifications\CreateCommentEventHandler` moved to
    `Elgg\Notifications\Handlers\CreateComment`
  - `Elgg\Notifications\MakeAdminUserEventHandler` moved to
    `Elgg\Notifications\Handlers\MakeAdminUser`
  - `Elgg\Notifications\MentionsEventHandler` moved to
    `Elgg\Notifications\Handlers\Mentions`
  - `Elgg\Notifications\RemoveAdminUserEventHandler` moved to
    `Elgg\Notifications\Handlers\RemoveAdminUser`
  - `Elgg\Notifications\UnbanUserEventHandler` moved to
    `Elgg\Notifications\Handlers\UnbanUser`
  - `Elgg\Notifications\CreateContentEventHandler` moved to
    `Elgg\Notifications\Events\CreateContent`
  - `Elgg\Notifications\EnqueueEventHandler` moved to
    `Elgg\Notifications\Events\Enqueue`
  - `Elgg\Notifications\MentionsEnqueueEventHandler` moved to
    `Elgg\Notifications\Events\MentionsEnqueue`
- Multiple notification handlers on the same action are now possible
  (e.g., `ban`, `user` with different messages per recipient)
- `elgg_unregister_notification_event()` now also requires a `$handler`
  parameter
- `array $actions` is replaced by a single `string $action` in both
  `elgg_register_notification_event()` and
  `elgg_unregister_notification_event()`

### Widgets Add Panel

- The widget add panel route is replaced by an ajax view

### Actions

- `admin/site/flush_cache` is renamed to `admin/site/cache/clear`

### Events

- The legacy `forward` event is removed in favor of the `response` event

## Plugin changes

### Entity related forms and actions

- `forms/blog/save` is now `forms/blog/edit`; `action/blog/save` is now
  `action/blog/edit`
- `forms/bookmarks/save` is now `forms/bookmarks/edit`;
  `action/bookmarks/save` is now `action/bookmarks/edit`
- `forms/discussion/save` is now `forms/discussion/edit`;
  `action/discussion/save` is now `action/discussion/edit`
- `forms/file/upload` is now `forms/file/edit`; `action/file/upload` is
  now `action/file/edit`

### Site Pages / External Pages

- Separate subtypes for each page are merged into a single
  `external_page` subtype
- The `expages/edit` action is replaced by the generic
  `EntityEditAction` controller
- `ElggExternalPage` entity fields are available in the fields service
- Extra external pages are extendable via the `'names', 'externalpages'`
  event

### Group route definitions

- The `subpage` variable is dropped from `collection:object:blog:group`,
  `collection:object:bookmarks:group`, and
  `collection:object:page:group` — this could break user favorites
- `requests:group:group` is renamed to
  `collection:user:user:group_requests`

### Groups

- The `group/edit` form and action now use a singular `owner_guid` value

### Likes

- By default only content owners can see who likes their content; a new
  plugin setting makes this public

### Members

- `collection:user:user` is now `collection:user:user:all`;
  `search:user:user` is now `collection:user:user:search`; related
  language keys are renamed

### Messages

- The `messages/send` form and action parameter `recipients` is renamed
  to `recipient` and contains a singular value

### Profile

- The `Twitter` profile field is removed

### Webservices

- REST API responses now send
  `Content-Disposition: attachment; filename="result.<view>"`
- Error responses use proper HTTP status codes (e.g., `404 Not Found`,
  `403 Forbidden`, `500 Internal Server Error`) instead of `200 OK`

## Changes in functions

### Changed function return types

- `elgg_register_external_file()`, `elgg_register_pam_handler()`,
  `elgg_register_route()`, `elgg_unregister_external_file()`, and
  `elgg_unregister_menu_item()` now return void

### Changed class function return types

- `\Elgg\Traits\Di\ServiceFacade::name()` now returns a `string`

### Removed Classes

- `\Elgg\Email\Address` — use `\Symfony\Component\Mime\Address` as a
  replacement
- `\Elgg\Email\HtmlPart`
- `\Elgg\Email\PlainTextPart`
