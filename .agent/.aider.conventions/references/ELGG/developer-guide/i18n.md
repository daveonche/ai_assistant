Make your UI translatable into many different languages.

## Language fallback

- The default language is `en` (English). Elgg falls back in this order:
  1. the language of the user
  2. the site language
  3. English

## Storing translations

- Translations are stored in PHP files in the `/languages` directory of your
  plugin; one file per language, named `/languages/{language-code}.php` where
  `{language-code}` is the ISO 639-1 short code:

```php
<?php // mod/example/languages/en.php

return [
    'example:text' => 'Some example text',
];
```

- To override an existing translation, include it in your plugin's language
  file and make sure your plugin is ordered later on the Admin > Plugins page:

```php
<?php // mod/better_example/languages/en.php

return [
    'example:text' => 'Some better text!',
];
```

- Unless you are overriding core's or another plugin's language strings, start
  language keys with your plugin name (e.g. `yourplugin:success`,
  `yourplugin:title`) to avoid conflicts with other language keys.

## Server-side API

`elgg_echo($key, $args, $language)` outputs the translation of the key in the
current language:

```php
echo elgg_echo('example:text');
```

- Variable replacement uses `vsprintf` syntax:

```php
// 'welcome' => 'Welcome to %s, %s!'
echo elgg_echo('welcome', [
    elgg_get_config('sitename'),
    elgg_get_logged_in_user_entity()->getDisplayName(),
]);
```

- Force the language with the third parameter:

```php
echo elgg_echo('welcome', [], $user->getLanguage());
```

- Test whether a translation exists before using it:

```php
$key = 'key:that:might:not:exist';
if (!elgg_language_key_exists($key)) {
    $key = 'fallback:key';
}

echo elgg_echo($key);
```

- Some APIs allow creating translations for new keys; translators should
  always include an English translation as a fallback. This makes
  `elgg_language_key_exists($key)` a reliable way to predict whether
  `elgg_echo($key)` will succeed.

## Javascript API

- `i18n.echo(key, args)` is like `elgg_echo` in PHP.
- Client-side translations are loaded asynchronously; require the `elgg/i18n`
  module to ensure translations are available:

```js
import i18n from 'elgg/i18n';

alert(i18n.echo('my_key'));
```
