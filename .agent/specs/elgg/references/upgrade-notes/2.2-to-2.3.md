# Plugin Upgrade Notes: 2.2 to 2.3

Delta guidance for updating Elgg plugins from 2.2 to 2.3, distilled from
<https://learn.elgg.org/en/stable/appendix/upgrade-notes/2.2-to-2.3.html>.
The transition raises the PHP requirement, deprecates a batch of APIs in
favor of new services, and adds response, upload, image, and URL-signing
APIs.

## PHP version

PHP 5.5 reached end of life in July 2016; new installations now require
PHP 5.6. Existing installations may stay on PHP 5.5 until Elgg 3.0. When
upgrading to 2.3 with composer on PHP 5.5, the `--ignore-platform-reqs`
flag may be needed.

## Deprecated APIs

- Registering for the `to:object` hook by extender name — use the
  `to:object, annotation` and `to:object, metadata` hooks instead.
- `ajax_forward_hook()` — no longer the handler for the `'forward', 'all'`
  hook; Ajax responses are now wrapped by the `ResponseFactory`.
- `ajax_action_hook()` — no longer the handler for the `'action', 'all'`
  hook; output buffering now starts before the hook is triggered in
  `ActionsService`.
- `elgg_error_page_handler()` — no longer used as a handler for
  `'forward', <error_code>` hooks.
- `get_uploaded_file()` — use the new file uploads API instead.
- `get_user_notification_settings()` — use
  `ElggUser::getNotificationSettings()`.
- `set_user_notification_setting()` — use
  `ElggUser::setNotificationSetting()`.
- The `pagesetup, system` event — use the menu or page shell hooks instead.
- `elgg.walled_garden` JavaScript — use the `elgg/walled_garden` AMD module
  instead.
- `elgg()->getDb()->getTableprefix()` — use `elgg_get_config('dbprefix')`.
- Private `update_entity_last_action()` — refrain from manually updating
  the last action timestamp.
- Setting a non-public `access_id` on metadata is deprecated (see the
  metadata section below).
- `get_resized_image_from_existing_file()` — use `elgg_save_resized_image()`.
- `get_resized_image_from_uploaded_file()` — use `elgg_save_resized_image()`
  in combination with the upload API.
- `get_image_resize_parameters()` will be removed.
- `elgg_view_input()` — use `elgg_view_field()`.

## Deprecated views

- `resources/file/world` — use the `resources/file/all` view instead.
- `resources/pages/world` — use the `resources/pages/all` view instead.
- `walled_garden.js` — use the `elgg/walled_garden` module instead.

## New API for page and action handling

Page handlers and action script files should return an instance of
`\Elgg\Http\ResponseBuilder`, built with these convenience functions:

- `elgg_ok_response()` sends a 2xx response with HTML (page handlers) or
  JSON data (actions).
- `elgg_error_response()` sends a 4xx or 5xx response without content/data.
- `elgg_redirect_response()` silently redirects the request.

## New API for working with file uploads

- `elgg_get_uploaded_files()` returns an array of Symfony uploaded file
  objects.
- `ElggFile::acceptUploadedFile()` moves an uploaded file to Elgg's
  filestore.

## New API for manipulating images

The new image manipulation service implements a more efficient approach to
cropping and resizing:

- `elgg_save_resized_image()` crops and resizes an image to preferred
  dimensions.

## New API for events

- `elgg_clear_event_handlers()` — like `elgg_clear_plugin_hook_handlers`,
  removes all registered event handlers.

## New API for signing URLs

URLs can be signed with a SHA-256 HMAC key and validated at any time before
URL expiry — usable for tokenizing action URLs in email notifications and
for other uses outside the Elgg installation:

- `elgg_http_get_signed_url()` signs the URL with the HMAC key.
- `elgg_http_validate_signed_url()` validates a signed URL.
- `elgg_signed_request_gatekeeper()` validates the signature of the current
  request.

## Extendable form views

Form footer rendering can be deferred until the form view and its
extensions have finished rendering, so plugins can collaborate on form
views without breaking the markup logic:

- `elgg_set_form_footer()` sets the form footer for deferred rendering.
- `elgg_get_form_footer()` returns the currently set form footer.

## Metadata `access_id`

Creating metadata with an explicit `access_id` other than `ACCESS_PUBLIC`
is deprecated. In Elgg 3.0, metadata will not be access controlled and will
be available in all contexts — plugins relying on access control of
metadata should migrate that storage to annotations or entities.

## New API for extracting class names from arrays

Like `elgg_extract()`, `elgg_extract_class()` extracts the `class` key (if
present), merges it into existing class names, and always returns an array.

## Notifications

- A high-level `'prepare', 'notification'` hook now fires for instant and
  subscription notifications and can alter notification objects
  irrespective of their type.
- The `'format', 'notification:<method>'` hook now fires for instant and
  subscription notifications and can format the notification (e.g. strip
  HTML tags, wrap the body in a template).
- Instant notifications are now handled by the notifications service, so
  almost all hooks applicable to subscription notifications also apply to
  instant notifications.
- `elgg_get_notification_methods()` returns the registered notification
  methods.
- Added `ElggUser::getNotificationSettings()` and
  `ElggUser::setNotificationSetting()`.

## Entity list functions can output tables

In functions like `elgg_list_entities($options)`, table output is possible
by setting `$options['list_type'] = 'table'` and providing an array of
table columns as `$options['columns']`. Each column is an
`Elgg\Views\TableColumn` object, usually created via methods on the
`elgg()->table_columns` service. Plugins can provide or alter these factory
methods (see `Elgg\Views\TableColumn\ColumnFactory`); see the
`admin/users/newest` view for a usage example.

## Inline tabs components

The inline tabs component renders through the `page/components/tabs` view
and can switch between pre-populated and ajax-loaded tabs. See
`page/components/tabs` in core views and `theme_sandbox/components/tabs` in
the developers plugin for usage instructions and examples.

## API to alter registration and login URLs

- `elgg_get_registration_url()` returns the site's registration URL.
- `elgg_get_login_url()` returns the site's login URL.
- The `registration_url, site` hook alters the default registration URL.
- The `login_url, site` hook alters the default login URL.

## Support for fieldsets in forms

- `elgg_view_field()` replaces `elgg_view_input()`; the API is similar but
  accepts a single array.
- `elgg_view_field()` supports `#type`, `#label`, `#help`, and `#class`,
  allowing unprefixed versions to be sent to the input view's `$vars`.
- The new `input/fieldset` view renders a set of fields, each rendered with
  `elgg_view_field()`.

## Lightbox

- Lightbox CSS is no longer loaded as an external CSS file; the lightbox
  theme now extends `elgg.css` and `admin.css`.
- The default lightbox config is defined via the `'elgg.data', 'site'`
  server-side hook.
