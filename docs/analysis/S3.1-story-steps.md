Story S3.1 Implementation Steps:

Step 1. Enable confirmation that the pinned release reference agrees across the installer, the documented install instructions, and the tested install command
Must Support:
- A repeatable check that compares the reference recorded inside the installer, every reference appearing in the documented install addresses, and the reference captured by the tested install command
- A clear pass/fail outcome identifying which locations disagree, naming the file and the differing references
- A check confirming the agreed reference is the currently pinned release tag
Manual Verification:
- Run the project's verification suite and observe the release-consistency checks report passing
- Temporarily change the reference in one location and re-run the checks to observe a failure message naming that location and both references, then restore it
Prerequisite: The pinned release reference must exist in the installer, the documentation, and the tested install command
Developer Notes:
- The checks should be executable from the project root with a single command
- Failure messages should state what to update and where

Step 2. Enable resolution of any detected reference inconsistency within a single change
Must Support:
- A defined remediation path: if any check reports a mismatch, every affected location is corrected to the same reference in one change
- Re-running the full verification suite after the correction and observing it pass with a clean repository state
Manual Verification:
- Review the recorded change (if one was needed) and confirm every location the failure messages named is corrected to the same reference
- Re-run the verification suite and observe all release-consistency checks passing
Prerequisite: Step 1 must be complete, so the checks reliably identify any mismatched location
Developer Notes:
- If the checks pass on the current tree, record that outcome as the evidence of completion
- Keep any correction confined to the locations the failure messages identified

Step 3. Enable recorded evidence of the passing verification
Must Support:
- A captured record of the verification run outcome showing all release-consistency checks passing against the current tree
- A summary noting that no inconsistency was found (or describing the fix applied)
Manual Verification:
- Locate the recorded evidence and confirm it reflects a full passing run of the verification suite
- Confirm the recorded summary matches the actual state of the three pinned locations
Prerequisite: Step 2 must be complete, so the recorded evidence reflects the final, consistent state
Developer Notes:
- Evidence may be a captured output log or a written summary kept with the project's records
- The evidence should be dated and traceable to the verification run
