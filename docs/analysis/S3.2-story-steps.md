Story S3.2 Implementation Steps:

Step 1. Enable confirmation that the release tag guard job triggers on version-tag pushes and enforces the pinned reference
Must Support:
- A repeatable check that the release tag guard job in the automated validation pipeline is triggered by pushes of version tags matching the project's version-tag pattern
- A confirmation that the job's steps compare the pushed tag against the reference pinned inside the installer and fail the pipeline when they disagree
- A clear pass/fail outcome from the workflow-definition verification
Manual Verification:
- Run the workflow-definition verification suite and observe the release-tag-guard checks report passing
- Inspect the pipeline definition and confirm the tag-push trigger pattern and the tag-versus-pinned-reference comparison are present
Prerequisite: The release tag guard job must exist in the automated validation pipeline definition
Developer Notes:
- The check should be executable from the project root with a single command
- Any structural assertion should reference the existing workflow-verification test patterns

Step 2. Enable confirmation that all pipeline action references remain pinned to verified full-length commit SHAs
Must Support:
- A repeatable check that every action reference in the automated validation pipeline resolves to a full-length commit SHA, not a moving tag or branch name
- Consistency with the verified-pin process recorded in the technology-stack documentation
- A clear pass/fail outcome naming any reference that is not SHA-pinned
Manual Verification:
- Run the workflow-definition verification suite and observe the action-pinning checks report passing
- Inspect the pipeline definition and confirm every action reference is a full-length commit SHA
Prerequisite: Step 1 must be complete, so the guard job's own definition is confirmed valid before auditing its action references
Developer Notes:
- The technology-stack documentation records the verified SHAs; cross-check against it rather than re-verifying remotely
- Report the count of pinned references as part of the outcome

Step 3. Enable recorded evidence of a green pipeline run on the current main branch
Must Support:
- A captured record of a passing pipeline run on the current main branch, including the run's identification and date
- A summary noting that the release tag guard verification criteria were all confirmed
- A dated, traceable evidence file kept with the project's records
Manual Verification:
- Locate the recorded evidence and confirm it reflects a passing pipeline run on the current main branch
- Confirm the recorded summary matches the actual pipeline definition state confirmed in Steps 1 and 2
Prerequisite: Step 2 must be complete, so the recorded evidence reflects a pipeline whose definition has passed all structural verification
Developer Notes:
- Evidence may be captured output or a written summary referencing the run
- The evidence should be dated and traceable to the pipeline run
