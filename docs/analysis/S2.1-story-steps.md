Story S2.1 Implementation Steps:

Step 1. Enable single-command acquisition of the assistant files
Must Support:
- A single command run from inside a project repository retrieves the installer
- The installer completes with only the documented host prerequisites present
- No additional prerequisites are required beyond what the readme already lists
Manual Verification:
- Run the single command in a fresh project repository and observe the installer start
- Confirm no missing-prerequisite error appears on a machine with the documented prerequisites
Prerequisite: None
Developer Notes:
- Keep the entry point discoverable and stable so users can fetch it on demand
- Focus on a frictionless first run with no manual preparation

Step 2. Enable clean-install placement of the assistant files
Must Support:
- Detection that the project has no existing assistant files
- Retrieval of the assistant files from a fixed, published release reference
- Placement of the assistant directory and entry script into the project root
- No leftover temporary artifacts after the install finishes
Manual Verification:
- Run the installer in an empty project repository and observe the assistant files appear
- Confirm the temporary retrieval location is removed after completion
Prerequisite: Step 1
Developer Notes:
- Retrieve from a fixed published reference so repeated installs are reproducible
- Prefer the simplest retrieval that leaves the project history clean

Step 3. Enable repeatable updates through the project's own history
Must Support:
- Detection that assistant files already exist
- Refresh of the files so the change is recorded as a normal, reviewable project change
- A warning before existing local customizations are replaced
Manual Verification:
- Re-run the installer in a project that already has the assistant files and observe the update path
- Review the project's change history to see the update as a reviewable, revertable change
- Observe the overwrite warning before the update proceeds
Prerequisite: Step 2
Developer Notes:
- Keep updates visible and reversible through the project's own change history
- Name the affected configuration area in the warning so users know what to re-apply

Step 4. Enable executable entry scripts that survive mode-insensitive environments
Must Support:
- Entry scripts are runnable immediately after install or update
- Executability is recorded explicitly so it survives environments that do not preserve file modes
- The source repository records executability for both entry scripts
Manual Verification:
- After install, run the entry script and observe it starts
- Inspect the recorded file modes and confirm both entry scripts are marked executable
Prerequisite: Step 2
Developer Notes:
- Record executability explicitly rather than relying on the local environment
- Verify the recorded modes in both the source repository and the installed project

Step 5. Enable documented install and update procedures
Must Support:
- One-command install instructions in the project readme
- Update instructions covering the repeatable update path
- The fixed-reference caveat explained for users
Manual Verification:
- Follow the readme instructions in a fresh project and complete an install without help
- Follow the update instructions in an existing install and complete an update
Prerequisite: Step 3
Developer Notes:
- Write for a user who has never seen the project; include what to expect at each step
- Keep the caveat next to the instructions it affects

Step 6. Enable installer conformance with project quality checks
Must Support:
- The installer passes the project's standard static checks for scripts
- The installer follows the project's script conventions
Manual Verification:
- Run the project's standard checks and observe them pass with the installer present
- Review the installer against the script-conventions checklist
Prerequisite: Step 2
Developer Notes:
- Run the checks before considering the installer complete
- Keep the script small enough to review in one pass
