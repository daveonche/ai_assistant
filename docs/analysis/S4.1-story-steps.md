Story S4.1 Implementation Steps:

Step 1. Enable project-root configuration counterpart discovery
Must Support:
- Detection of same-named counterparts, in the project root, of each of the four supported configuration files
- Per-file independence, so a mix of present and absent counterparts is handled correctly
- Unchanged behavior when only the assistant-default copies exist
Manual Verification:
- Place a same-named configuration file in the project root and start a session with command tracing enabled; observe the launch picks up the counterpart
- Remove the counterpart and start a session again; observe behavior identical to a project with no counterparts
Prerequisite: None
Developer Notes:
- Perform discovery in a single pass before launch arguments are assembled
- Keep the outcome observable so users can confirm which files were detected

Step 2. Enable combined value-based configuration with project-root precedence
Must Support:
- One effective combined file per pair for each of the three value-based configuration files
- Conflicting values resolved in favor of the project-root counterpart
- Assistant-default values retained for entries the project root does not set
- Identical combined output for identical inputs on repeated runs
Manual Verification:
- Provide a project-root file that overrides one assistant default and adds one new entry; observe inside the assistant that the override takes effect and the untouched default still applies
- Re-run with the same inputs and observe the same combined result both times
Prerequisite: Step 1
Developer Notes:
- Combine nested structures level by level instead of replacing whole sections
- Keep combined intermediates out of the user's way, and clean them up after the session

Step 3. Enable combined ignore patterns
Must Support:
- A union of ignore patterns from the assistant default and the project-root counterpart, so patterns from both apply
- Duplicate patterns counted once
- A deterministic, order-independent result
Manual Verification:
- Add one distinct ignore pattern to each of the two ignore files; observe inside the assistant that both patterns are excluded
- Swap the order in which the patterns appear and observe the same result
Prerequisite: Step 1
Developer Notes:
- Treat the two pattern sources as equal contributors to one combined set
- Preserve the meaning of each source pattern in the combined result

Step 4. Enable documented merge behavior
Must Support:
- Documentation describing which files merge, the precedence rules per file, and the expected file formats
- Placement in the existing setup and prerequisite documentation so first-time users find it
Manual Verification:
- A reader following only the documentation can create a project-root override and correctly predict the combined outcome before running the assistant
Prerequisite: Steps 2 and 3
Developer Notes:
- Keep the wording consistent with the existing setup guide structure
- Include both the override case and the no-counterpart case in the explanation

Step 5. Enable verification coverage for merge behavior
Must Support:
- Automated checks covering the merge case, the precedence rules, the pattern union, and the no-counterpart pass-through
- A mixed case where some counterparts exist and others do not
- The checks running alongside the existing verification suites
Manual Verification:
- Run the full verification suite and observe all checks, including the new ones, pass
Prerequisite: Steps 2 and 3
Developer Notes:
- Assert on observable launch behavior rather than internal details
- Keep each check focused on one rule so failures point at the exact behavior
