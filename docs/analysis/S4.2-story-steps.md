Story S4.2 Implementation Steps:

Step 1. Enable seeded framework conventions delta files
Must Support:
- Framework-named conventions files (the seeded ELGG.md and RAILS.md) exist in
  .agent/.aider.conventions/, one per seeded framework
- Each file contains only delta guidance: details the assistant would not already
  know on its own (e.g., local deviations from framework defaults, project- or
  environment-specific constraints, pointers to version-specific references), rather
  than restating general framework knowledge
- The conventions reference directory layout accommodates version-specific framework
  conventions keyed by framework name and version (e.g., references/ELGG/v7), so a
  framework conventions file can reference version-specific guidance when it exists
- Each file stays valid whether or not any version-specific conventions are present
- Both files follow the project's documentation conventions
Manual Verification:
- Open each new file and confirm it is lean and contains only non-obvious delta
  guidance, with no restatement of general framework knowledge and no placeholder
  text
- Confirm both files pass the project's documentation conventions checks
Prerequisite: None
Developer Notes:
- Keep each file lean: the assistant already knows each framework's general
  practices, so the file's value lies in what is unique to this project or
  environment
- Keep each file self-contained so it can be loaded on demand without other references
- Model the files' structure on the existing reference documents in the same directory
- Keep framework files version-stable: version-specific guidance belongs in the
  conventions reference directory, keyed by framework name and version, so adding a
  framework version does not require editing the framework conventions file

Step 2. Enable project framework detection guidance
Must Support:
- Orchestration guidance instructs the assistant to inspect framework indicators under
  the project's source directory to identify the framework in use
- Orchestration guidance instructs the assistant to inspect root manifests and
  configuration files as additional framework indicators
- When the project indicators reveal the framework version, detection captures it
  alongside the framework name
- Detection concludes with an identified framework before coding guidance is offered
- When no indicators are found, detection concludes that no framework is identified
Manual Verification:
- In a project whose indicators clearly point to one framework, ask the assistant
  which framework it detects and observe it names the expected framework
- In a project whose indicators also reveal the framework version, observe the
  assistant reports that version alongside the framework name
- In a project with no framework indicators, ask the assistant and observe it reports
  that no framework was identified
Prerequisite: None
Developer Notes:
- The detection guidance lives in the assistant's orchestration instructions, not in
  launcher or runtime code
- Phrase indicators generically (dependency manifests, configuration files, directory
  layout) so detection works across project types
- Detection informs guidance only; it should not modify or generate project files

Step 3. Enable framework-agnostic conventions recommendation
Must Support:
- The assistant discovers available framework conventions by scanning the framework-
  named files in .agent/.aider.conventions/, rather than relying on a fixed
  framework-to-file mapping, so adding a new framework requires only adding its
  conventions file
- When the detected framework matches an available conventions file, the assistant
  recommends loading that file via the /read-only command, outputting the command
  inline rather than executing it itself
- When the matched framework conventions file references version-specific conventions
  under the conventions reference directory and the project's framework version is
  identifiable, the assistant also recommends loading the matching version-specific
  reference
- The recommendation follows the routing conventions established in the orchestration
  documentation
- The routing table in the orchestration documentation gains the framework-based
  routing rule as a generic name-matching rule alongside the existing file-type rules
- When the detected framework has no matching conventions file, the assistant makes no
  recommendation and continues with existing default conventions
Manual Verification:
- In a project matching one of the seeded framework files, confirm the assistant
  recommends loading the matching conventions file with an inline /read-only command
- In a project whose framework version is identifiable and a matching version-specific
  reference exists, confirm the assistant also recommends loading that reference
- In a project whose detected framework has no matching conventions file, confirm the
  assistant makes no recommendation and proceeds without error
- Review the routing table and confirm the framework-based rule is documented as a
  generic name-matching rule next to the existing file-type rules
Prerequisite: Steps 1 and 2 (the matching files exist and detection guidance is in place)
Developer Notes:
- Matching is performed against what the conventions directory actually contains, so
  the set of recommendable frameworks grows automatically with the directory contents
- The recommendation wording should mirror how existing routing entries direct the
  assistant to load reference files
- Keep the no-match behavior explicit so the assistant remains usable in projects
  without a matching conventions file
- This step only extends guidance documentation; no launcher or runtime behavior
  changes
