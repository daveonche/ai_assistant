# Story S1.2 Implementation Steps:

Step 1. Enable Dockerfile Creation
Must Support:
- Creation of `Dockerfile.aider` in the project root.
- Specification of `paulgauthier/aider-full:latest` as the base image.
- Installation of system dependencies (ca-certificates, curl, gnupg, libpulse0, alsa-utils, chromium).
- Installation of Docker CLI, Docker Compose plugin, and Node.js v22.
- Installation of Mermaid CLI (`@mermaid-js/mermaid-cli`).
- Configuration of Puppeteer to use the system Chromium browser.
- Creation of `/home` directory with appropriate permissions.
- Creation of a Puppeteer config file to run without sandbox.
Manual Verification:
- Verify that `Dockerfile.aider` exists in the project root.
- Verify that the first instruction is `FROM paulgauthier/aider-full:latest`.
- Verify that the Dockerfile includes installation steps for Node.js, Docker CLI, Chromium, and Mermaid CLI.
- Verify that the Puppeteer environment variables and config are set.
Prerequisite: None
Developer Notes:
- Use standard Dockerfile syntax.
- Ensure the Dockerfile sets up the environment for diagram rendering and Docker-in-Docker capabilities.

Step 2. Enable Docker Image Building in Script
Must Support:
- The `ai-assistant.sh` script must contain logic to build the Docker image from `Dockerfile.aider`.
- The script should tag the image as `aider-agent:latest`.
- The script should run the build process in the background and display a spinner with status messages.
- The script should handle build failures by displaying the last lines of the build log.
Manual Verification:
- Run the build command portion of `ai-assistant.sh`.
- Verify that the Docker image is built successfully (e.g., `docker images` shows `aider-agent:latest`).
- Verify that a spinner is displayed during the build process.
Prerequisite: Step 1
Developer Notes:
- Use `docker build -t aider-agent:latest -f Dockerfile.aider .` command.
- Redirect build output to a temporary log file and parse it for status updates.

Step 3. Enable Container Execution and Volume Mapping in Script
Must Support:
- The `ai-assistant.sh` script must execute `docker run` to start the container.
- The script must map the current working directory to the container and set it as the working directory.
- The script must map local user configuration files (`.gitconfig`, `.bashrc`) and Aider cache directories (`.cache/aider`) into the container.
- The script must map the Docker socket (`/var/run/docker.sock`) and Docker config (`$HOME/.docker`) for Docker-in-Docker.
- The script must map Pulse Audio and `/dev/shm` for audio support.
- The script must pass necessary environment variables (e.g., API keys from `.env`, `HOME=/home`, `PYTHONUNBUFFERED=1`, `PULSE_SERVER`).
- The script must run the container with the current user and group, and add the `docker` and `audio` groups.
- The script must pass `--chat-mode ask "$@"` to the Aider command inside the container.
- The script must include logic to clean up orphaned containers from previous sessions.
Manual Verification:
- Run `./ai-assistant.sh`.
- Verify that the container starts and drops into the Aider interface in ask mode.
- Verify that changes made by Aider inside the container are reflected in the local directory.
- Verify that orphaned containers are cleaned up.
Prerequisite: Step 2
Developer Notes:
- Use `docker run -it --rm` for an interactive, ephemeral container.
- Use `-v "$(pwd):$(pwd)"` and `-w "$(pwd)"` to map and set the working directory.
- Use `--env-file .env` to pass environment variables.
- Use `--user "$(id -u):$(id -g)"` to run as the current user.
